# 🚀 Alpha-Soft Task Tracker

REST API таск-трекера на Django REST Framework с ролевой моделью, изоляцией данных, фильтрацией и авто-документацией. Разработан в рамках учебного проекта УрФУ.

---

## 📋 О проекте

Система позволяет управлять проектами и задачами в команде разработки. Каждый пользователь может быть владельцем проекта, участником, автором задачи или исполнителем — с соответствующими правами доступа.

### ✨ Основные возможности
- 🔐 Регистрация и авторизация пользователей (через сессии Django Admin)
- 📁 Создание проектов с назначением владельца и участников
- 📝 Управление задачами: заголовок, описание, приоритет, статус, дедлайн, исполнитель
- 👥 Ролевая модель: владелец / исполнитель / автор / участник
- 🔒 Полная изоляция данных: пользователи видят только свои проекты и задачи
- 🔍 Фильтрация задач по проекту, статусу, приоритету, исполнителю, дедлайну
- 📄 Пагинация ответов (20 записей на страницу)
- 📚 Автоматическая документация API (Swagger + ReDoc)
- 🖥️ Простой тестовый интерфейс для ручной проверки (`/ui/`)

## 📦 Установка и запуск

### 1. Клонируйте репозиторий
```bash
git clone https://github.com/voronovalubove-web/alpha-tracker.git
cd alpha-tracker
```

### 2. Создайте и активируйте виртуальное окружение
```bash
# macOS / Linux
python -m venv venv
source venv/bin/activate

# Windows (CMD)
python -m venv venv
venv\Scripts\activate.bat

# Windows (PowerShell)
python -m venv venv
venv\Scripts\Activate.ps1
```

### 3. Установите зависимости
```bash
pip install -r requirements.txt
```

### 4. Примените миграции
```bash
python manage.py migrate
```

### 5. Создайте суперпользователя (для входа в админку и тестовый UI)
```bash
python manage.py createsuperuser
# Следуйте подсказкам: username, email, password
```

### 6. Запустите сервер разработки
```bash
python manage.py runserver
```

✅ Сервер доступен по адресу: **http://127.0.0.1:8000/**

## 🌐 Доступные эндпоинты

### 🔹 Основной интерфейс
| Путь | Описание |
|------|----------|
| `/ui/` | Простой тестовый веб-интерфейс для создания проектов и задач |
| `/admin/` | Django Admin панель (управление пользователями, проектами, задачами) |

### 🔹 API (все запросы требуют авторизации)
| Метод | Путь | Описание |
|-------|------|----------|
| `GET` | `/api/users/me/` | Данные текущего пользователя |
| `GET` | `/api/users/` | Список всех пользователей (только `id`, `username`) |
| `GET` | `/api/projects/` | Список проектов пользователя |
| `POST` | `/api/projects/` | Создать проект (автоматически назначает `owner`) |
| `GET` | `/api/projects/{id}/` | Детали проекта |
| `PATCH` | `/api/projects/{id}/` | Обновить проект (добавить/удалить `members`) |
| `DELETE` | `/api/projects/{id}/` | Удалить проект (только владелец) |
| `GET` | `/api/tasks/` | Список задач с фильтрацией и пагинацией |
| `POST` | `/api/tasks/` | Создать задачу (автоматически назначает `author`) |
| `GET` | `/api/tasks/{id}/` | Детали задачи |
| `PATCH` | `/api/tasks/{id}/` | Обновить задачу (ограничено по ролям) |
| `DELETE` | `/api/tasks/{id}/` | Удалить задачу (автор или владелец) |

### 🔹 Фильтрация задач
Добавляйте параметры к `/api/tasks/`:
```
?project=1&status=new&priority=high&assignee=3&deadline__gte=2026-05-01
```

| Параметр | Описание | Пример |
|----------|----------|--------|
| `project` | Фильтр по ID проекта | `?project=1` |
| `status` | Статус: `new`, `in_progress`, `done`, `closed` | `?status=new` |
| `priority` | Приоритет: `low`, `medium`, `high`, `urgent` | `?priority=high` |
| `assignee` | Фильтр по ID исполнителя | `?assignee=3` |
| `deadline__gte` | Дедлайн не раньше даты | `?deadline__gte=2026-06-01` |
| `deadline__lte` | Дедлайн не позже даты | `?deadline__lte=2026-12-31` |

### 🔹 Документация API
| Путь | Описание |
|------|----------|
| `/api/docs/` | Интерактивная консоль Swagger UI (можно тестировать запросы) |
| `/api/redoc/` | Статичная, красиво оформленная документация ReDoc |
| `/api/schema/` | Сырая OpenAPI 3.0 схема в формате YAML/JSON |

## 🔐 Ролевая модель и права доступа

| Роль | Проекты | Задачи |
|------|---------|--------|
| **Владелец проекта** | ✅ Создаёт, редактирует, удаляет, управляет участниками | ✅ Полный доступ ко всем задачам проекта |
| **Исполнитель задачи** | 🔍 Только просмотр (если участник) | ✏️ Может менять `статус` и `приоритет` своей задачи |
| **Автор задачи** | 🔍 Только просмотр (если участник) | ✏️ Может редактировать `описание`, 🗑️ удалять свою задачу |
| **Участник проекта** | 🔍 Только просмотр | 🔍 Только просмотр задач проекта |
| **Не участник** | ❌ Не видит проект (404) | ❌ Не видит задачи (404) |

> ⚠️ **Изоляция данных**: если пользователь не является владельцем или участником проекта, он **никогда** не получит доступ к его задачам — даже при прямом запросе `/api/tasks/{id}/` сервер вернёт `404 Not Found`.

## 🧪 Тестирование

### Через тестовый UI
1. Откройте **http://127.0.0.1:8000/ui/**
2. Если видите `❌ Не авторизован` — сначала войдите в **/admin/** под созданным суперпользователем
3. После авторизации:
   - Создайте проект → кликните на него → добавьте участников
   - Перейдите во вкладку «Задачи» → создайте задачу, назначьте исполнителя из списка участников
   - Проверьте фильтрацию и отображение

### Через API-клиент (Postman / curl)
```bash
# Авторизация: сначала войдите через /admin/ в браузере,
# затем в клиенте укажите заголовок:
Cookie: sessionid=ВАШ_ИД_СЕССИИ

# Или используйте токен-аутентификацию (если подключите)

# Пример создания проекта:
curl -X POST http://127.0.0.1:8000/api/projects/ \
  -H "Content-Type: application/json" \
  -H "X-CSRFToken: ВАШ_CSRF" \
  -d '{"name": "Мой проект", "members": [1, 2]}' \
  --cookie "sessionid=ВАШ_ИД"

# Пример создания задачи:
curl -X POST http://127.0.0.1:8000/api/tasks/ \
  -H "Content-Type: application/json" \
  -H "X-CSRFToken: ВАШ_CSRF" \
  -d '{"title": "Исправить баг", "project": 1, "priority": "high", "assignee": 2}' \
  --cookie "sessionid=ВАШ_ИД"
```

### Проверка прав доступа
1. Создайте двух суперпользователя через `createsuperuser`
2. Под первым создайте проект и задачу
3. Под вторым попробуйте получить `/api/projects/{id}/` → должен вернуться `404`
4. Добавьте второго пользователя в `members` проекта → теперь он видит проект и задачи

### Смена базы данных на PostgreSQL
1. Установите драйвер: `pip install psycopg2-binary`
2. В `settings.py` замените `DATABASES`:
```python
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'NAME': os.getenv('DB_NAME', 'alpha_tracker'),
        'USER': os.getenv('DB_USER', 'postgres'),
        'PASSWORD': os.getenv('DB_PASSWORD', ''),
        'HOST': os.getenv('DB_HOST', 'localhost'),
        'PORT': os.getenv('DB_PORT', '5432'),
    }
}
```

## 🆘 Проблемы и вопросы

| Проблема | Решение |
|----------|---------|
| `TemplateDoesNotExist` | Убедитесь, что `APP_DIRS: True` в `TEMPLATES`, и файл лежит в `tasks/templates/tasks/` |
| `CSRF verification failed` | Проверьте `CSRF_TRUSTED_ORIGINS` в `settings.py` и передавайте заголовок `X-CSRFToken` |
| `403 Forbidden` при POST | Убедитесь, что авторизованы через `/admin/` и передаёте куки сессии |
| Пустой список участников в UI | Откройте `F12` → `Console`, проверьте, что `/api/users/` возвращает данные |
| Миграции не применяются | Удалите `db.sqlite3` и `tasks/migrations/0001*.py`, затем заново `makemigrations` → `migrate` |
